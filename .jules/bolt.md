## 2026-07-21 - Parallelize stock fetching in stores
**Learning:** Found sequential API calls (N+1 queries) inside `for...of` loops in `fetchStock` methods of Pinia stores (`product.ts` and `productInventory.ts`). This blocked the main execution flow unnecessarily as each request waited for the previous one.
**Action:** Replaced sequential `for...of` loops with `await Promise.all(productIds.map(async (productId) => {...}))` to fire network requests concurrently, significantly reducing data load latency for large product groupings (like ship groups).
## 2026-07-24 - Parallelize fetching in fetchRoutingEditorEnums
**Learning:** Found sequential API calls inside `for...of` loops in `fetchRoutingEditorEnums` of the `util` Pinia store. This blocked the main execution flow unnecessarily as each request waited for the previous one. A previous comment noted that parallelizing was not done because of race conditions in `fetchEnums` merging logic. I had to fix the race condition in `fetchEnums` (by directly merging into `this.enums` within the response handler instead of capturing a snapshot beforehand) before safely converting the loop to `Promise.all`.
**Action:** Replaced sequential `for...of` loops with `await Promise.all` to fire network requests concurrently and updated the state merging logic to be concurrent-safe. Always verify state mutation logic is safe before parallelizing previously sequential requests.
